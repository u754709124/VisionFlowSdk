# Vision.Flow.Core 开发约束

本文件适用于 `src/Vision.Flow.Core` 及其全部子目录，并补充仓库根目录 `AGENTS.md`。

## Core 边界

- Core 只承载流程模型、执行引擎、校验、序列化、Adapter 契约和基础流程节点，不得加入
  具体上位机、设备 SDK、算法、数据库、图片存储或项目专属业务类型。
- Core 基础节点必须保持通用、UI 无关，并能在生产运行时不加载 Designer 程序集执行。

## 节点输出协议

- 输出必须至少表达一种明确语义：节点新产生或修改后的值、执行状态、外部操作回执、
  诊断信息，或者资源所有权转移。
- 禁止仅为串联方便而原样透传输入业务对象。运行时允许读取控制流拓扑中的任意前置节点
  输出，下游不需要逐节点接力同一对象。
- 禁止为同一个值保留两个同义名称，例如 `Result` 与 `IsMatched` 同时承载同一布尔值。
  每个稳定语义只能有一个规范输出名。
- 诊断输出可以回显解析后的设置、比较操作数、实际执行参数或外部响应，但必须明确标注
  诊断用途，且不得与主业务结果使用同义名称。
- 类型化值与通用 Object 不得重复输出同一对象。已知引用类型使用准确 `ObjectType`；
  只有协议确实接收任意对象时才允许无类型 Object。
- 业务值和所有权句柄不是同义输出。若 Core 契约引入 lease，必须明确所有者、借用范围、
  克隆和释放时机，禁止用裸 Value 替代所有权转移。

## 版本与兼容

- 删除、重命名、收紧输出类型或改变所有权语义属于破坏性协议变更，必须提升 Descriptor
  主版本，搜索并迁移 samples、tests、docs 以及上下游仓库中的流程绑定。
- 不得以“兼容”为由永久保留同义输出。确需过渡时必须有明确迁移版本、弃用说明和删除点。
- Descriptor 声明必须与节点所有运行路径返回的输出键一致，默认输出校验也必须同步更新。

## 测试要求

- 基础节点测试必须断言完整输出名称集合，覆盖成功、等待、错误和取消等实际输出路径。
- 对协议收敛增加负向断言，确认旧别名、输入透传和无类型 Object 不再出现。
- 修改 Core 节点后运行 `build/test.ps1`；涉及 Designer 变量候选或发布校验时同时覆盖相关
  Designer 与 Validation 测试。
